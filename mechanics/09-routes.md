# 09. Маршруты и их согласование

Константы — `BALANCE.routes`. Связанные документы: линии ОТ и назначение — 05; торговля и бюджет — 03; подрегионы, владельцы и ИИ-соседи — 08; UI — 06.

**Главное правило.** Внутри своих подрегионов игрок создаёт маршруты сам, без согласований. Маршрут, который проходит хотя бы через один чужой подрегион (`Subregion.owner` ≠ инициатор и ≠ −1), требует согласия **всех** владельцев по пути: игроков в мультиплеере и ИИ-соседей. Через свободные подрегионы (`owner = −1`) согласие не нужно: маршрут допускается, а после выкупа участка новый владелец наследует действующее соглашение на оставшийся срок (08 §5).

## 1. Типы маршрутов
| Масштаб | Определение | Согласование |
|---|---|---|
| Внутригородской `intraCity` | все остановки/рёбра в одном городе и во владениях инициатора | нет |
| Внутрирегиональный `intraRegion` | несколько городов/подрегионов, все принадлежат инициатору или свободны | нет |
| Межрегиональный `interRegion` | хотя бы одно ребро проходит по чужому подрегиону | все владельцы по пути |

| Груз | Режим | Объект в коде | Тарификация транзита |
|---|---|---|---|
| Пассажирский | Автобус | `Line`, `LINE_TYPES[0]`, по `RoadNet` | ₽/ТС-км |
| Пассажирский | Трамвай / Метро | `LINE_TYPES[1]`, `[2]`, собственные пути | ₽/ТС-км + доля выручки |
| Пассажирский | Поезд (ж/д) | `LINE_TYPES[3]` | ₽/ТС-км + доля выручки |
| Грузовой | Авто (грузовики) | маршрут-заказ (05 §6), `Line.cargo=true` | ₽/т-км |
| Грузовой | Ж/д | `Line.cargo=true`, `LINE_TYPES[3]` | ₽/т-км |
| Транзит авто жителей | обычные дороги | общие дороги (08 §5) | без заявки, по соглашению о соединении |

Метро через чужой подрегион требует согласия, даже если оно целиком под землёй: станции и вентшахты стоят на чужой земле.

## 2. Заявка `RouteApproval`
```ts
interface RouteApproval {
  id: number; routeId: number; initiator: OwnerId;
  approvers: { owner: OwnerId; km: number; status: 'pending' | 'approved' | 'rejected' | 'countered'; deadline: GameDay }[];
  terms: { tollPerVehKm: number; tollPerTonKm: number; revenueShare: number; termMonths: number;
           withdrawNoticeDays: number; withdrawPenaltyShare: number };
  status: RouteStatus; history: { day: GameDay; from: RouteStatus; to: RouteStatus; by: OwnerId; note?: string }[];
}
```
Условия по умолчанию: плата 15 ₽/ТС-км (пасс.) или 0,5 ₽/т-км (груз), доля выручки 5 % сверх пропорции пробега, срок 24 мес (допустимо 6–120), уведомление об отзыве 60 дней, штраф за отзыв 25 % годового дохода маршрута на территории отзывающего.

## 3. Жизненный цикл (статусы)
| Статус | id | Смысл | Маршрут работает? |
|---|---|---|---|
| Черновик | `draft` | инициатор рисует маршрут и задаёт условия; сеть показывает, чьи участки затронуты | нет |
| Отправлена | `submitted` | заявка разослана всем владельцам, таймеры запущены | нет |
| На рассмотрении | `review` | хотя бы один владелец открыл заявку или прислал встречное предложение | нет |
| Согласована частично | `partial` | часть владельцев согласилась, остальные думают | нет (можно строить на своей территории) |
| Активна | `active` | согласны все; маршрут работает, начисления идут | да |
| Оспорена | `disputed` | сторона заявила нарушение условий (неуплата, превышение объёма, изменение трассы) | да, но выплаты по спорной части замораживаются (эскроу) |
| Приостановлена | `suspended` | идёт период уведомления после отзыва согласия, или инициатор поставил паузу, или спор решён против инициатора | нет (ТС в депо, содержание идёт) |
| Отозвана | `withdrawn` | инициатор закрыл маршрут, или период уведомления истёк | нет, финал |
| Истекла | `expired` | закончился срок или вышел таймаут ответа | нет, финал (можно продлить новой заявкой) |
| Отклонена | `rejected` | хотя бы один владелец отказал | нет, финал |

### Переходы
```
draft ──submit──▶ submitted ──open/counter──▶ review
submitted|review ──первый approve──▶ partial ──все approve──▶ active
submitted|review|partial ──любой reject──▶ rejected
submitted|review|partial ──таймаут ответа──▶ expired        (молчание = отказ, см. §7)
review ──counter принят инициатором──▶ submitted (условия обновлены, approve сброшены у всех)
active ──claim нарушения──▶ disputed ──решено в пользу инициатора──▶ active
                                     └─решено против──▶ suspended
active ──отзыв согласия владельцем──▶ suspended (после withdrawNoticeDays)   // в течение уведомления остаётся active с флагом
active|suspended ──инициатор закрыл──▶ withdrawn
suspended ──повторное согласие / изменение трассы в обход──▶ submitted
suspended ──прошло withdrawNoticeDays без решения──▶ withdrawn
active ──termMonths истёк──▶ expired   (за 30 дней — автопредложение продления: новая заявка с теми же условиями)
```
Изменение трассы активного маршрута, затрагивающее новый или другой чужой участок, порождает новую заявку. Пока она рассматривается, работает старая трасса.

### Отзыв согласия
Владелец может отозвать согласие в любой момент. Тогда:
1. Маршрут работает ещё `withdrawNoticeDays` = 60 дней.
2. Отзывающий платит инициатору `withdrawPenaltyShare · годовой доход маршрута на его территории`, если отзывает раньше срока без нарушения со стороны инициатора.
3. Отношения −15 (`relationOnWithdraw`).

**Пример**: доход маршрута на территории B 1,2 млн ₽/год → штраф 300 тыс ₽.

## 4. Решение ИИ-соседей
ИИ отвечает за `aiResponseDays` = 3 игровых дня. Скоринг:
```
benefit   = clamp((tollIncome + revenueShareIncome + tradeGain + accessGain) / (costs + 1) / 2, 0, 1)
risk      = clamp(0.5·V/C_добавка_на_его_рёбрах + 0.3·конкуренция_с_его_линиями + 0.2·(termMonths/120), 0, 1)
relationN = relation / 100
strategic = 1, если маршрут связывает его с рынком, где у него дефицит товаров или пробки (05, 03 §5); 0.5 нейтрально; 0, если усиливает его конкурента в тендере (08 §3)
score = 0.45·benefit − 0.2·risk + 0.2·relationN + 0.15·strategic + 0.2   // +0.2 центрирует шкалу на ~[0..1]
threshold = 0.55 + profile.thresholdShift
```
- `score ≥ threshold` → согласие.
- `threshold − 0.15 ≤ score < threshold` (`counterBand`) → **встречное предложение**: ИИ поднимает плату до `toll · profile.tollMult` или долю выручки на +5 п.п., либо сокращает срок вдвое, чтобы его оценка дошла до порога. Не больше `maxCounterOffers` = 3 раундов на заявку.
- иначе → отказ с причиной (наибольший отрицательный вклад: «пробки на моём шоссе», «конкуренция с моим трамваем», «низкие отношения»).

| Профиль | Кто (по `CITY_KINDS`) | Сдвиг порога | Множитель платы |
|---|---|---|---|
| `cooperative` | торговый, курортный | −0,10 | 0,8 |
| `mercantile` | портовый | 0 | 1,3 |
| `cautious` | аграрный | +0,10 | 1,0 |
| `protectionist` | промышленный | +0,20 | 1,5 |

**Пример**: ж/д через B (`cautious`, порог 0,65). benefit 0,6, risk 0,3, relation 60, strategic 1 → 0,27 − 0,06 + 0,12 + 0,15 + 0,2 = 0,68 ≥ 0,65 → согласие. При relation 40: 0,64. Это попадает в полосу встречного предложения, и ИИ просит плату 15 ₽/ТС-км (`tollMult` 1,0), но срок 12 мес.

## 5. Экономика маршрута
### Доходы и расходы инициатора (в месяц)
```
revenue  = Σ пассажиров·fare  (или т·тариф_груза)
costs    = n_veh·upkeep·24·30 (05 §5) + путь_км·trackUpkeep + Σ_чужие toll + Σ revenueShare_выплаты + амортизация
амортизация = vehCost·n_veh/(15·12) + стройка_пути/(40·12)
```
`trackUpkeep`: для ОТ на дорогах — 0 (дорогу содержит владелец, 03 §6), для собственных путей — 1 % `kmCost` в год.

### Распределение выручки между регионами
1. Каждый транзитный владелец получает **плату за проезд**: `toll·ТС-км на его территории` (груз: `т-км`).
2. Сверх этого **доля выручки** распределяется по пассажиро-км (груз: т-км) на территориях:
```
share_r = revenueShare · revenue · pkm_r / Σ pkm   (по всем чужим территориям)
```
3. Остальное получает инициатор. Пассажиро-км считаются по реальной загрузке на перегонах (05 §5), а не по длине.

**Пример**: межрегиональный поезд A→B→C, 100 км: A (инициатор) 40 км, B 35 км, C 25 км; 6 составов, по 24 рейса в день на состав. Выручка 9 млн ₽/мес, pkm по территориям 40/35/25 %.
- Плата за проезд B: 15·(6·24·35)·30 = 2,27 млн; C: 15·(6·24·25)·30 = 1,62 млн.
- Доля 5 %: 0,45 млн делится между B и C по 35:25 → B 0,26 млн, C 0,19 млн.
- Содержание 6·2 600·720 = 11,2 млн → без субсидий маршрут убыточен. Нужно поднять тариф, сократить число составов или договориться о плате ниже (встречное предложение A). На этом примере видно, зачем условия переговорные.

### Споры
Поводы: неуплата платы за проезд (баланс инициатора < 0 два месяца подряд), превышение заявленного объёма грузов на > 20 %, изменение трассы без заявки. При `disputed` выплаты по спорной части идут в эскроу на `disputeDays` = 30 дней. Решение: для ИИ — автоматически по фактам (метрики симуляции однозначны); в мультиплеере — по фактам, при неоднозначности побеждает заявитель с компенсацией из эскроу. Отношения −5 у обеих сторон.

## 7. Синхронность в мультиплеере
- Заявки — **асинхронные** объекты на сервере-арбитре (источник истины). Изменения статусов — события с игровым днём и id автора; клиенты применяют их детерминированно.
- Таймаут ответа: `responseTimeoutDays` = 15 игровых дней для онлайн-игрока. Если игрок офлайн, — `offlineTimeoutDays` = 30 игровых дней, но не меньше реального окна `offlineProxyRealHours` = 48 ч.
- После реального окна за офлайн-игрока решает **ИИ-заместитель** по его выбранному профилю (§4), если игрок включил это в настройках. Иначе молчание = отказ → `expired`.
- Скорость игры в мультиплеере общая (минимальная из голосов) или игровое время региона идёт независимо. Таймауты всегда считаются в днях региона-получателя, чтобы паузой нельзя было «держать» заявку.
- Отзыв согласия и споры ставятся в очередь и применяются на границе игрового дня, одновременно у всех. Конфликт одновременных действий (approve и withdraw в один тик) разрешается порядком прихода на сервер.
- Одиночная игра: те же механики, все соседи — ИИ.

> Вовлечение: цепочки «Новые земли»/«Добрые соседи», события «Тендер», «Предложение соседа о маршруте», контракты — 10 §2–3, §8 (P8).

> Линии ОТ по остановкам и их экономика — 15; межрегиональная линия создаёт `RouteApproval` (15 §1).
