# 04. Модель темпов роста от потребностей

Пересчёт — раз в игровой день (`growthEveryTicks` = 1440). Константы — `BALANCE.growth`. Жёсткого предела нет: рост замедляется, когда потребности не удовлетворены, и ускоряется, когда есть избыток работы, жилья, товаров и доступности.

## 1. Уровни агрегации
| Уровень | Что хранит | Размер |
|---|---|---|
| Ячейка роста `GrowthCell` | спрос R/C/I, факторы, счётчики гистерезиса | 256×256 м (`cellSize`), 16×16 тайлов (`TILE`=16) |
| Город `CityInfo.id` | агрегаты: население, рабочие места, цены, налоги | 1 на город |
| Регион | миграция между городами | 1 |

Гигаполис 32 768 м → 128×128 = 16 384 ячеек; пересчёт ячейки ≈ 50 операций → < 1 мс в воркере.

## 2. Нормированные факторы (каждый ∈ [−1..1])
Все факторы — по ячейке, с подмешиванием городского значения (`f = 0.6·f_cell + 0.4·f_city`), чтобы окраины чувствовали город целиком.

| Фактор | Формула | Смысл |
|---|---|---|
| `jobs` (для R) | `clamp((jobsReach − workforce·0.96)/(workforce·0.96 + 1), −1, 1)` | есть ли работа в 45 мин доступности |
| `housingVacancy` | `clamp((0.05 − vacancy)/0.05, −1, 1)` | мало свободного жилья → спрос растёт |
| `goods` | `2·goodsSatisfaction − 1` | |
| `access` | `clamp((45 − avgCommuteMin)/30, −1, 1)` | транспортная доступность |
| `congestion` | `−clamp((avgVC − 0.7)/0.5, 0, 1)` | только штраф: пробки с V/C > 0,7 |
| `tax` | `−(taxX − taxNeutral)/(taxMax − taxNeutral)` = `−(t − 0.10)/0.20` | ниже 10 % — бонус до +0,5 |
| `attractiveness` | `0.4·(landValueNorm−0.5)·2 + 0.3·(parks) + 0.3·(1−2·pollution)` | парки, вода, низкое загрязнение |
| `customers` (для C) | `clamp((retailDemand − retailCapacity)/retailCapacity, −1, 1)` | |
| `workers` (для C/I) | `clamp((workforceReach − jobs)/jobs, −1, 1)` | хватает ли работников в 45 мин |
| `freightAccess` (для I) | `clamp(1 − freightCostPerTon/300, −1, 1)` | дешевизна вывоза до склада/станции/порта |
| `inputs` (для I) | `2·inputSatisfaction − 1` | хватает ли сырья |
| `exportPrice` (для I) | `clamp((price/basePrice − 1)·2, −1, 1)` | |

## 3. Сырой спрос
```
D_R_raw = 0.30·jobs + 0.15·housingVacancy + 0.10·goods + 0.15·access + 0.10·congestion + 0.10·tax + 0.10·attractiveness
D_C_raw = 0.40·customers + 0.20·goods + 0.20·access + 0.10·tax + 0.10·workers
D_I_raw = 0.30·workers + 0.25·freightAccess + 0.20·inputs + 0.15·exportPrice + 0.10·tax
```
Сумма весов каждого спроса = 1 → `D ∈ [−1..1]`.

## 4. Сглаживание и защита от колебаний
1. **EMA**: `D ← D + demandSmoothing·(D_raw − D)`, alpha 0,15/день → полупериод ≈ 4,3 дня.
2. **Мёртвая зона**: при `|D| < deadband` (0,05) — ничего не строится и не сносится.
3. **Гистерезис**: апгрейд здания требует `D > deadband` `hysteresisDays` = 3 дня подряд; даунгрейд — `D < −deadband` 3 дня подряд.
4. **Лимит скорости**: в ячейке за день не более `maxUpgradesPer1000 · max(1, pop_cell/1000)` (2 на 1000 жит.) апгрейдов уровня.
5. **Задержка стройки**: новый уровень появляется как «стройка» на 2–5 дней, ёмкость добавляется по окончании — это естественный лаг, гасящий колебания «пробки → отток → нет пробок → приток».
6. **Асимметрия**: снос медленнее роста: `decayDailyMax` = 0,2 % ёмкости в день.

## 5. Темп роста
```
rate_X = baseDailyRate · D_X · damp(P_city)          // baseDailyRate = 0.004 (0,4 %/день)
ΔCapacity_X(cell) = rate_X · max(Capacity_X(cell), seed_X)   при D_X > deadband
ΔCapacity_X(cell) = −min(decayDailyMax, |rate_X|) · Capacity_X(cell)   при D_X < −deadband
```
`seed_X` — стартовая ёмкость пустой зоны: 1 уровень на тайл зоны (чтобы зонирование пустыря начало застраиваться).

Ёмкость переводится в здания: выбирается тайл зоны с наибольшей стоимостью земли и уровнем ниже `maxL_cell` (старт = `SIZES[i].maxL`, **не лимит**: см. 08 §9 — при устойчивом спросе `maxL_cell` растёт на 2 без предела). Также см. фронтир-бонус `frontierDemandBonus` (08 §7).

### 5.1 Пример
Город 120 тыс, ячейка в спальном районе: jobs = +0,4, housingVacancy = +0,6 (вакантность 2 %), goods = +0,2, access = −0,1 (52 мин), congestion = −0,3 (V/C 0,85), tax = 0, attractiveness = +0,1.
`D_R_raw = 0.12 + 0.09 + 0.02 − 0.015 − 0.03 + 0 + 0.01 = 0.195`.
damp(120 000) = (2 000 000/2 120 000)^0,3 = 0,983.
rate = 0,004·0,195·0,983 = 0,077 %/день → ≈ 2,3 %/мес → ≈ 32 %/год, если факторы не изменятся. На практике рост «съедает» jobs и vacancy, и D падает к 0 — город сам находит равновесие, пока игрок не снимет ограничение.

## 6. Масштабирование на очень большие города
```
damp(P) = (P0 / (P0 + P))^gamma,   P0 = 2 000 000, gamma = 0.3
```
| Население | damp | Эффективный макс. рост (D=1) %/мес |
|---|---|---|
| 10 тыс | 0,999 | 12,0 |
| 120 тыс | 0,983 | 11,8 |
| 1 млн | 0,885 | 10,6 |
| 3 млн | 0,760 | 9,1 |
| 10 млн | 0,584 | 7,0 |
Демпфер никогда не обнуляется — потолка нет. Абсолютный прирост у крупного города всё равно больше (3 млн·9 % ≫ 120 тыс·12 %).

Производительность: при P > 1 млн ячейки обновляются **по кругу** порциями (1/4 ячеек в день, с `dt=4` дня), городские агрегаты — каждый день.

## 7. Миграция между городами
Раз в месяц: `migr_AB = 0.002 · pop_A · (attr_B − attr_A)⁺ · connected(A,B)`, `attr = 0.5·happiness + 0.3·D_R + 0.2·jobs`. Ограничение — свободное жильё в B. Это переносит «избыточный» спрос в соседние города, связанные дорогой/ж/д, и мотивирует строить межгородской транспорт.

## 8. Влияние налогов — сводка
Ставка 10 % нейтральна. Каждые +5 п.п. → `tax` −0,25 → `D_R` −0,025 (≈ −0,3 %/мес роста). 0 % → +0,05 к D (рост +0,6 %/мес), но бюджет теряет весь жилой налог.
