# 12. Пробки

Расширяет 05 §4 (BPR и назначение MSA). Сегменты, полосы, узлы — 11. Константы — `BALANCE.congestion` (07) плюс `transport.bprAlpha/bprBeta`, `laneCapacityPerHour`. Шаг макро-назначения — 360 тиков (6 игр. ч), микро-агенты `Traffic` — каждый тик (1 игр. мин).

## 1. Загрузка ребра
```
V_dir = автопоездки/1.3 + автобусы·2 + трамваи(tramShared)·2·0.35 + грузовики·2.5        // PCU/ч, 05 §4
C_dir = Σ_car-полос laneCapacityPerHour[класс] · Π capacityMult модулей (11 §8) · k_incident · k_spill
x = V_dir / C_dir                                                                        // V/C
t_link = t0 · (1 + 0.15 · x^4)                       // BPR, t0 = len / v (v из 11 §9)
```
Автобусная (`bus`) и обособленная трамвайная (`tramDedicated`) полосы в C авто не входят; ТС на них едут с `t0`.

## 2. Задержки на узлах
Стоимость пути = Σ t_link + Σ d_node(вход→выход). Задержка считается **по подходу** (входящее ребро узла) раз в пересчёт назначения.

### 2.1 Приоритет (`priority`, `stopAll`)
Главная дорога: d = 0. Второстепенный подход — ёмкость по свободным интервалам главного потока:
```
c_minor = V_major · exp(−V_major · tc/3600) / (1 − exp(−V_major · tf/3600))      // tc = 6.5 с, tf = 3.5 с
d_minor = 3600/c_minor + 900·T·[(x−1) + sqrt((x−1)² + (3600/c_minor)·x/(450·T))] + 5     // HCM, T = 0.25 ч, x = V_minor/c_minor; с
```
`stopAll`: каждый подход c = 1 800/n_подходов, d по той же формуле + 4 с на остановку.

### 2.2 Светофор (`signal`) и кольцо (`roundabout`)
Доля зелёного распределяется пропорционально критическим потокам подходов: `g_i/C = (1 − L/C) · y_i / Σ y`, где `y_i = V_i/s_i`, `s_i = 1 800·полос` авт/ч, потерянное время `L = 4 с` на фазу, цикл `C = 90 с` (`roads.signalCycleSec`).
```
c_i = s_i · g_i/C
d_i = 0.5·C·(1 − g_i/C)² / (1 − min(1, x_i)·g_i/C)  +  900·T·[(x_i−1) + sqrt((x_i−1)² + 4x_i/(c_i·T))]     // Вебстер + перегрузочная часть, с
```
Кольцо: `c_entry = 1 400 − 0,7·V_circ` авт/ч на полосу входа (не ниже 200), d — формула 2.1.

**Пример**: проспект 2 полосы (s = 3 600), V = 1 500, поперечная улица s = 1 800, V = 500. y = 0,417 и 0,278; L/C = 8/90 = 0,089 → g/C = 0,911·0,6 = 0,547 и 0,364. c = 1 969 и 655; x = 0,76 и 0,76. d₁ = 45·0,205/(1 − 0,416) = 15,8 с + перегрузочная часть 225·(−0,24 + 0,253) = 2,8 с ≈ **19 с**; d₂ = 45·0,405/(1 − 0,277) = 25,2 + 225·(−0,24 + 0,276) = 8,1 ≈ **33 с**.

### 2.3 Слияния, горлышки, переходы
- `merge` (въезд на шоссе): ёмкость правой полосы шоссе после слияния = `C_lane − 0,8·V_ramp`; если `V_ramp > ramp-ёмкость(1 800)` — очередь на ramp (§5).
- `taper` (сужение N→N−1): `C_down = (N−1)·C_lane·0,95`.
- `transition` (шоссе → улица): светофор/кольцо, как 2.2.
- Штраф за левый поворот через встречный поток без отдельной фазы: +`leftTurnPenaltySec` 6 с × (V_встр/1 000).

Ограничение: `d_node ≤ maxNodeDelaySec` = 600 с (для устойчивости назначения; выше — коллапс, §4).

## 3. Динамическая стоимость пути и объезды
### 3.1 Макро (MSA, 05 §4)
Обобщённая стоимость авто (05 §2) использует `t_link + d_node`. Тёплый старт: каждый пересчёт делает `msaIterations` = 4 итерации, шаг `1/(k+1)` со сквозным счётчиком k (сбрасывается после крупного изменения сети), что гасит колебания между пересчётами.

### 3.2 Осведомлённость водителей
Не все переключаются на объезд сразу. Доля трафика, который **перераспределяется** за один пересчёт:
```
share_react = awareShare · clamp((GC_old − GC_best) / GC_old − rerouteThreshold, 0, 1) / (1 − rerouteThreshold)
```
`awareShare` = 0,35 (навигатор/опыт), `rerouteThreshold` = 0,10 (выигрыш < 10 % игнорируется), плюс абсолютный порог `rerouteMinGainMin` = 2 мин. Остальные 65 % идут привычным путём до следующего пересчёта.

### 3.3 Гистерезис против колебаний
- Сегмент, с которого трафик ушёл, не может принять обратно больше `hysteresisShare` = 50 % ушедшего объёма в следующем пересчёте.
- Стоимость, по которой выбирают путь, — сглаженная: `t̃ ← t̃ + 0.5·(t − t̃)` (EMA с alpha `costSmoothing` 0,5 за пересчёт).
- При крупном изменении (новый сегмент, авария, перекрытие) — внеочередной локальный пересчёт (§6).

### 3.4 Микро-агенты
Видимые машины (`Traffic`, ≤ 4 000, 05 §7) берут маршрут из макро-путей; раз в `agentRerouteTicks` = 30 тиков агент, стоящий в очереди > 3 мин, с вероятностью `awareShare` перестраивает остаток пути Дейкстрой по текущим `t̃` в радиусе 2 км.

## 4. Уровни пробки и оверлей
| Уровень | id | V/C (x) | Средняя скорость / свободная | Цвет | Hex |
|---|---|---|---|---|---|
| Свободно | `free` | < 0,6 | > 0,98 | зелёный | `#3cb043` |
| Плотно | `dense` | 0,6–0,9 | 0,9–0,98 | жёлтый | `#f2c230` |
| Затор | `jam` | 0,9–1,2 | 0,75–0,9 (+очереди) | красный | `#e04848` |
| Коллапс | `gridlock` | > 1,2 или очередь заполнила ребро | < 0,4 | бордовый | `#7a1020` |

Совпадает с 06 §3 и порогом оповещения `alerts.congestionVC` = 0,9. Скорость считается из полной задержки (`len/(t_link + d_node_avg)`), а не только BPR, поэтому коллапс фиксируется по очереди: ребро с заполненной очередью получает `gridlock` независимо от x. Оверлей рисует **направление** отдельно (две полосы цвета для двусторонних).

## 5. Распространение затора вверх по потоку
Очередь на подходе за интервал Δt = 6 ч в пике считается для пикового часа:
```
Q = max(0, V_in − C_eff) · 1 ч       // авт.
queueLen = Q · vehSpacing / nLanes    // vehSpacing = 7 м
```
Если `queueLen > len` ребра, излишек «переливается» на входящие рёбра пропорционально их потоку, а ёмкость этих рёбер снижается:
```
k_spill = clamp(1 − (queueLen − len)/len_upstream, spillMinCap, 1)        // spillMinCap = 0.2
```
Перелив проходит не больше `spillMaxHops` = 4 рёбер вверх (ограничение производительности). Это даёт видимые «хвосты» — главную визуальную причину решать пробки.

Микро-агенты читают `queueLen` и останавливаются в хвосте (уже есть `v.wait` в `Traffic.step`).

## 6. Аварии и перекрытия
```
p_accident(ребро, день) = accidentRatePerMVehKm · V_day · len_km / 1e6 · (1 + 2·max(0, x − 0.9))
```
`accidentRatePerMVehKm` = 0,8 (на миллион авт-км), растёт при заторе. Авария: `k_incident` = 0,5 (одна полоса закрыта) на `accidentDurationMin` 45 мин (30–90 случайно); на шоссе вызывает внеочередной локальный пересчёт: только пути, проходящие через ребро (≤ 5 % OD-пар), за 1 кадр воркера.

Перекрытия игрока (ремонт, праздник 10 §3) — `k_incident` = 0 на заданное число дней; стоимость пути = ∞, объезд — все водители (информированы заранее).

Пример: проспект 1 км, 20 000 авт/день, x = 1,0 → 0,8·0,02·(1 + 0,2) = 0,019 аварии/день ≈ 1 раз в 52 дня.

## 7. Производительность в браузере
| Мера | Решение |
|---|---|
| Граф маршрутизации | рёбра склеиваются через узлы `bend` (11 §6): в графе только узлы со степенью ≠ 2 |
| Что пересчитывать | полный MSA — раз в 6 игр. ч; между ними — только «грязные» рёбра: изменились за последний час на > 10 % (`dirtyThreshold`), их соседи до 2 переходов |
| Узлы | задержки узлов пересчитываются только для узлов с x подхода > 0,5 (остальные d ≈ const) |
| Очереди/перелив | только рёбра уровня `jam`/`gridlock`, обычно < 3 % сети |
| Аварии | проверка раз в игровой час по рёбрам с V > 0, вероятность пакетно |
| Массивы | `V`, `C`, `t̃`, `queueLen`, `level` — Float32Array/Uint8Array по id ребра, передаются в главный поток только для видимых чанков + уровни для оверлея (1 байт/ребро) |
| Бюджет | пересчёт задержек узлов ≤ 2 мс на 10 000 узлов; полный MSA растянут на 360 тиков (05 §4) |
