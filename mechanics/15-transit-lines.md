# 15. Линии общественного транспорта по остановкам

Линия — упорядоченный список остановок, по которому ходят ТС одного типа. Расширяет структуру `Line` из `src/sim/Transit.ts` (`stops`, `pts`, `L`, `n`, `fare`, `riders`, `revenue`, `cargo`, `cities`). Выбор режима и обобщённая стоимость — 05 §2–3, пропускная способность и подвижной состав рельса — 14 §5, согласование линий через чужие подрегионы — 09. Константы — `BALANCE.lines` (07) и `transport.*`.

## 1. Модель линии
```ts
interface TransitLine extends Line {
  stopIds: number[];                 // упорядоченно; кольцевая, если loop
  loop: boolean;                     // кольцо (одно направление) или маятник (туда-обратно)
  schedule: { period: PeriodId; headwayMin: number }[];   // §2
  vehicles: number[];                // id назначенных ТС
  autoVehicles: boolean;             // автоподбор (§4)
  segLoad: Float32Array;             // загрузка по перегонам, 2·(n−1) для маятника
  board: Float32Array; alight: Float32Array;   // посадки/высадки по остановкам за день
  approvalId?: number;               // заявка 09, если линия межрегиональная
}
interface Stop { id: number; x: number; z: number; node: number; type: number; lines: number[]; capacityPerHour: number }
```
Правила постройки: ≥ 2 остановок; расстояние между соседними остановками `stopSpacingMin`…`stopSpacingMax`: автобус/трамвай 250–800 м, метро 600–2 000 м, поезд 1 500–15 000 м (ближе — предупреждение «медленно», дальше — «пропуски охвата»). Путь между остановками — кратчайший по `RoadNet` (автобус, `tramShared`) или `RailNet` (14). Остановка, обслуживающая несколько линий, — одна `Stop` (общая ёмкость).

Статус линии: внутри своих подрегионов — сразу активна; если путь проходит по чужому подрегиону — создаётся `RouteApproval` (09 §2), линия в статусе `draft`/`submitted` и не работает до `active`.

## 2. Расписание и интервалы
Сутки делятся на периоды; в каждом свой интервал:
| Период | id | Часы | Доля суточных поездок | Интервал по умолч. (× базового) |
|---|---|---|---|---|
| Утренний пик | `amPeak` | 7–10 | 30 % | ×1 |
| День | `day` | 10–17 | 30 % | ×1,5 |
| Вечерний пик | `pmPeak` | 17–20 | 27 % | ×1 |
| Вечер | `evening` | 20–24 | 10 % | ×2 |
| Ночь | `night` | 0–7 | 3 % | ×4 или не ходит |

Пиковый час (05 §1) = 10 % суточных поездок, т.е. треть утреннего пика. Интервал ограничен `headwayMinMin`..`headwayMaxMin` = 2..30 мин (05 §5) и минимальным интервалом системы (14 §5). Число ТС в периоде: `n = ceil(cycleTime / headway)`, лишние ТС стоят в депо (содержание −70 %, `idleUpkeepShare` 0,3).

## 3. Спрос: посадки и высадки
1. Из транспортного назначения (05) берутся OD-потоки, выбравшие ОТ, и их пути по сети линий (кратчайший по GC с пересадками).
2. Для каждой пары (остановка посадки i, остановка высадки j) на линии ℓ накапливается `T_ij^ℓ` — **матрица посадок/высадок** (только для пар на одной линии; пересадка разбивает поездку на два участка).
```
board_i  = Σ_j T_ij        alight_j = Σ_i T_ij
segLoad_k = Σ_{i ≤ k < j} T_ij               // поток на перегоне k→k+1 (для обратного направления — отдельно)
load_k = segLoad_k(пиковый час) / capacity_h  // capacity_h = 60/headway · cap
pkm = Σ_k segLoad_k · len_k                    // пассажиро-км (для 09 §5)
```
3. Ограничение вместимости: если `load_k > 1`, у части поездок, проходящих перегон k, GC растёт на `crowding` (05 §5) и время ожидания +1 интервал (пропуск переполненного ТС) с долей `(load − 1)/load`; на следующем пересчёте часть уходит на другие режимы — естественное равновесие.

**Пример**: автобусная линия из 5 остановок A–E, пиковый час, одно направление:
| | B | C | D | E | board |
|---|---|---|---|---|---|
| A | 60 | 120 | 80 | 140 | 400 |
| B | | 40 | 60 | 100 | 200 |
| C | | | 30 | 90 | 120 |
| D | | | | 50 | 50 |
| alight | 60 | 160 | 170 | 380 | |

Загрузка перегонов: A→B 400, B→C 540, C→D 500, D→E 380. При интервале 5 мин ёмкость = 12·80 = 960 пасс/ч → макс. load = 540/960 = 0,56. При интервале 10 мин load B→C = 1,13 — переполнение.

## 4. Назначение подвижного состава
- Ручной режим: игрок задаёт число ТС, интервал = cycleTime/n.
- **Автоподбор** (`autoVehicles`, 10 §7.4): раз в игровой день по каждому периоду
```
n_target = ceil(cycleTime · maxSegLoad_period / (cap · 60 · targetLoad))      // targetLoad = 0.8
```
с ограничением интервала 2–30 мин, ёмкостью депо (14 §2) и бюджетом (`maxAutoUpkeepShare` — не больше 20 % месячного дохода города на ОТ без подтверждения). Изменение не больше ±20 % ТС в день (гистерезис).
- ТС берутся из депо системы; закупка новых — `vehCost` (`LINE_TYPES`), продажа — 50 % остаточной стоимости.
- Межрегиональные линии: ТС принадлежат инициатору (09 §5).

## 5. Прибыльность
```
revenue_month   = riders_day · fare · 30                          // fare — Line.fare, по умолч. transport.defaultFare
opCost_month    = Σ_периоды n_period · hours_period · upkeep · 30 + idle ТС · upkeep · 24 · 30 · 0.3
trackCost_month = путь_км · trackUpkeepPerKmMonth (14 §1)  (автобус — 0, дорогу содержит владелец, 03 §6)
amort_month     = n_max · vehCost / (vehicleLifeYears·12) + стройка_пути / (trackLifeYears·12)   // 15 и 40 лет, 09 §5
tolls_month     = транзитная плата и доли (09 §5), если линия межрегиональная
profit = revenue − opCost − trackCost − amort − tolls
opRatio = revenue / (opCost + trackCost)        paybackMonths = (стройка + ТС) / max(1, revenue − opCost − trackCost)
```
**Пример** (автобусная линия выше, маятник 8 км, 5 остановок): cycle = 2·8 000/(9·60) + 0,5·10 + 2·2 = 29,6 + 5 + 4 = 38,6 мин. Пик интервал 5 → 8 ТС, день 7,5 → 6, вечер 10 → 4, ночь — не ходит. ТС-часы в день: 8·6 + 6·7 + 4·4 = 106 → 106·350·30 = 1,11 млн ₽/мес; простой (8·24 − 106) = 86 ТС-ч·350·0,3·30 = 0,27 млн ₽/мес. Пассажиров: пиковый час 770 (Σ board, одно направление) ×2 направления / 0,1 = 15 400/день → 15 400·40·30 = **18,5 млн ₽/мес**. Амортизация 8·15 000/180 = 0,7 тыс ₽. Прибыль ≈ 18,5 − 1,11 − 0,27 = **+17,1 млн ₽/мес** (автобусы на загруженных коридорах очень прибыльны — это сигнал менять их на трамвай/метро по ёмкости, а не по деньгам).

Тариф влияет на спрос через GC (05 §2): +10 ₽ → +10·60/VOT мин (≈ +1,7 мин для среднего класса), т.е. эластичность ≈ −0,2…−0,4.

## 6. UI-метрики
| Элемент | Содержание |
|---|---|
| Редактор линии | клик по остановкам в порядке, перетаскивание, вставка между; превью длины, cycleTime, охвата (`catch`), стоимости |
| Профиль загрузки | столбики `segLoad/capacity` по перегонам для двух направлений; цвета как 12 §4 (зелёный < 0,6, жёлтый 0,6–0,9, красный 0,9–1,2, бордовый > 1,2) |
| Посадки/высадки | столбики `board/alight` по остановкам, матрица OD по клику (тепловая карта) |
| Расписание | таблица периодов: интервал, ТС, ёмкость, макс. load |
| Экономика | revenue, opCost, trackCost, amort, tolls, profit, opRatio, paybackMonths; график 12 мес |
| Сводка по сети | список линий: тип, пасс/день, opRatio, макс. load, статус (09 для межрегиональных); сортировка |
| Метрики `MetricsSnapshot` | `lineRidersDay[ℓ]`, `lineMaxLoad[ℓ]`, `lineProfit[ℓ]`, `lineOpRatio[ℓ]`, `stopBoardings[s]`, `transitShare` (06 §2.3) |
| Оповещения | `load > transitOverload` 1,1 (06 §4), линия убыточна 3 мес (opRatio < 0,5), остановка без пассажиров 30 дней, заявка по межрегиональной линии (09 §6) |
