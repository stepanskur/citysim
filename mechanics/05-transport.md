# 05. Транспортная модель

Двухуровневая модель: **макро** (агрегированные потоки по графу `RoadNet`, пересчёт каждые `assignmentEveryTicks` = 360 тиков) и **микро** (видимые агенты `Traffic`, `Transit`, каждый тик). Макро — источник истины для экономики и роста, микро — визуализация и локальные заторы. Константы — `BALANCE.transport`.

## 1. Генерация поездок
```
tripsDay(cell) = residents · tripsPerResidentDay (2.4)
цели: work 45 % · shop 30 % · leisure 25 %
```
Зоны OD — ячейки роста 256 м, на больших картах объединяются в **макрозоны** (≤ 1 024 зон; для гигаполиса 4×4 ячейки = 1 км). Распределение — гравитационная модель:
```
T_ij = O_i · A_j · exp(−β · GC_ij) / Σ_k A_k · exp(−β · GC_ik),   β = 0.05 1/мин
A_j: work → рабочие места, shop → розничная ёмкость, leisure → парки+COM
```
Пиковый час = 10 % суточных поездок (`peakHourShare`); назначение считается для пика, суточные показатели масштабируются.

## 2. Режимы и обобщённая стоимость
Обобщённая стоимость в **минутах** (деньги переводятся через стоимость времени VOT класса: 150 / 350 / 900 ₽/ч):
```
GC_m = t_inVeh + walkWeight·t_walk + waitWeight·t_wait + transfers·transferPenaltyMin
       + (fixedCost + costPerKm·km + fare + parking) · 60 / VOT_c + asc_m + crowding
```
| Режим | id | Скорость м/с | Фикс. ₽ | ₽/км | ASC мин | Макс. км |
|---|---|---|---|---|---|---|
| Пешком | `walk` | 1,3 | 0 | 0 | 0 | 2,5 |
| Велосипед | `bike` | 4,5 | 0 | 0 | 6 | 8 |
| Авто | `car` | по дороге (`ROAD_TYPES.speed`) с BPR | 30 | 12 | 0 | ∞ |
| Автобус | `bus` | 9 (`LINE_TYPES[0]`) | — | — | 4 | 40 |
| Трамвай | `tram` | 11 | — | — | 2 | 40 |
| Метро | `metro` | 20 | — | — | −2 | 80 |
| Поезд | `rail` | 30 | 0 | 2 | 0 | 400 |

`waitWeight` = 2, `walkWeight` = 1,8, пересадка = 5 мин. Ожидание = интервал/2. Доступ к ОТ — пешком до остановки в радиусе `LINE_TYPES[t].catch` (450/500/800/900 м). Парковка: `parkingCostMax·clamp(density/densityCenter)` до 200 ₽ (политика «платная парковка»).

## 3. Логит-выбор режима
```
P_m = exp(−θ·GC_m) / Σ_k exp(−θ·GC_k),   θ = logitTheta = 0.12 1/мин
```
Недоступные режимы (дальше `maxKm`, нет остановки, нет авто у низкого класса в 30 % случаев) исключаются.

**Пример** (средний класс, 6 км до работы, пик):
- Авто: дорога 6 км при 13 м/с → 7,7 мин, V/C 0,95 → ×(1+0,15·0,95⁴)=1,122 → 8,6 мин; деньги 30+72+парковка 100 = 202 ₽ → 202·60/350 = 34,6 мин. **GC = 43,2**.
- Метро: пешком 400 м ×2 = 10,3 мин ×1,8 = 18,5; ожидание 3 мин (интервал 6) ×2 = 6; в пути 5 мин; тариф 55 → 9,4; ASC −2. **GC = 36,9**.
- Автобус: пешком 2·250 м = 6,4 ×1,8 = 11,5; ожидание 5 ×2 = 10; в пути 11,1 мин (+ пробки ×1,122) = 12,5; тариф 40 → 6,9; ASC 4. **GC = 44,9**.
- exp(−0,12·GC): 0,0056 / 0,0119 / 0,0046 → **авто 25 %, метро 54 %, автобус 21 %**.

## 4. Загрузка дорог (BPR)
```
t_e = t0_e · (1 + bprAlpha · (V_e / C_e)^bprBeta),   alpha = 0.15, beta = 4
t0_e = len / ROAD_TYPES[type].speed
C_e  = lanes · laneCapacityPerHour[type]    // 700 / 1600 / 2000 / 400 авт/ч на полосу для Улица/Проспект/Шоссе/Переулок
V_e  = автопоездки/carOccupancy(1.3) + автобусы·2 + трамваи·2·congestion + грузовики·2.5   (PCU, авт/ч)
```
| V/C | Множитель времени |
|---|---|
| 0,5 | 1,009 |
| 0,8 | 1,061 |
| 1,0 | 1,15 |
| 1,2 | 1,31 |
| 1,5 | 1,76 |
| 2,0 | 3,40 |

**Назначение**: метод последовательных средних (MSA), `msaIterations` = 4 за пересчёт, с тёплым стартом от прошлого решения (фактически сходится за 3–4 пересчёта ≈ 1 игровой день). Кратчайшие пути — Дейкстра с бинарной кучей от каждой макрозоны; для 1 024 зон × ~200 тыс. рёбер ≈ 1 024·0,02 с = 20 с CPU → разбивается на порции по 1/32 зон за тик воркера (≈ 0,6 с на пересчёт растянуто на 360 тиков).

## 5. Общественный транспорт
Линия — `Line` из `src/sim/Transit.ts` (тип, остановки, `fare`, `riders`, `revenue`).
```
cycleTime_min = 2L/(speed·60) + 0.5·stops       // L — длина маршрута в одну сторону, м; 0,5 мин стоянка
headway_min = cycleTime_min / n_veh
capacity_h  = n_veh · cap · 60 / cycleTime_min
load        = peakRiders_maxSegment / capacity_h
crowding    = crowdingPenaltyPerLoad · max(0, load − 0.8) · t_inVeh    // +50 % времени при load 1.8
```
Интервал ограничен `headwayMinMin`..`headwayMaxMin` = 2..30 мин. Тариф по умолчанию 40/45/55/120 ₽ (Автобус/Трамвай/Метро/Поезд), игрок меняет 0–300 ₽.

**Окупаемость линии в месяц** = `riders·fare·30 − n_veh·upkeep·24·30`.
Пример: автобус, 10 км, 12 ТС: цикл = 2·10 000/(9·60) + 0,5·30 = 52 мин → интервал 4,3 мин, ёмкость 12·80·60/52 = 1 108 пасс/ч. 9 000 пасс/день·40 ₽·30 = 10,8 млн; расходы 12·350·720 = 3,0 млн → +7,8 млн ₽/мес.
Метро 8 км, 10 составов: путь 8·260 000 = 2,08 млн, 8 станций·60 000 = 0,48 млн, составы 1,5 млн; цикл 2·8 000/1 200 + 4 = 17,3 мин → интервал 1,7 → ограничено 2 мин; ёмкость 10·1 100·60/17,3 = 38 150 пасс/ч.

## 5a. Маршруты и согласование
Линии `Line` внутри своих владений игрок создаёт сам; линия или грузовой маршрут, проходящий через чужие подрегионы, требует согласования всех владельцев — жизненный цикл, плата за проезд и делёж выручки по пассажиро-км в 09.

## 6. Грузы и логистика
- Заказ: розница/фабрика при запасе < 50 % цели формирует заказ `(товар, объём, получатель)`.
- Поставщик выбирается по минимальной `цена + доставка`; доставка = `т·км·costPerTonKm` (грузовик 6, ж/д 2, судно 1 ₽/т·км) + время × 0,5 ₽/т·мин.
- Грузовик 12 т; ж/д состав 20 вагонов × 60 т = 1 200 т. Порт — неограниченно (в пределах уровня `K.PORT`).
- Мультимодальность: склад/станция/порт — узлы перевалки (+40 ₽/т за перегрузку).
- Грузовики добавляются в поток V_e как 2,5 PCU; политика «запрет грузовиков в центре» убирает их с рёбер с `city` центра днём.

Пример: 13 грузовиков food/день для города 100 тыс (03 §4.4) ≈ 1,3 грузовика/ч в пик — заметно лишь на складских улицах.

## 7. Производительность (браузер)
| Мера | Решение |
|---|---|
| Агрегация | поездки — потоки по рёбрам (Float32Array по id ребра), не агенты |
| LOD агентов | видимые машины ≤ `maxVisibleCars` = 4 000 (InstancedMesh). Каждое ребро в кадре порождает `round(V_e · visFactor)` агентов, `visFactor` подбирается так, чтобы суммарно ≤ 4 000; вне камеры агенты не существуют |
| Микро → макро | агенты читают скорость ребра из BPR, а не наоборот (никаких обратных связей от визуализации) |
| Пересчёт | MSA в отдельном воркере, порциями; результаты — `Transferable` массивы |
| Память | граф в типизированных массивах (`RoadNet.serialize`) |
| Дальние зоны | макрозоны 1 км для гигаполиса, ячейки 256 м для остальных |

Бюджет: ≤ 4 мс/кадр в главном потоке (рендер агентов), симуляция-воркер ≤ 50 % одного ядра при x10.
