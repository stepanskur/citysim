# 01. Основной игровой цикл

Все числа — из `07-balance-constants.ts` (`BALANCE`). Время: **1 тик = 1 игровая минута** (`time.tickGameMinutes`), при скорости x1 тик длится 200 мс реального времени, **игровой день = 1440 тиков ≈ 4,8 мин** реального времени, месяц = 30 дней (≈2,4 ч при x1, ≈14 мин при x10), год = 12 месяцев. Скорости: пауза, x1, x3, x10.

## 1. Фантазия игрока
Игрок — мэр/транспортный управляющий региона из нескольких процедурных городов (`World.cities: CityInfo[]`). Города уже живут на старте (от посёлка ≈2 тыс. до гигаполиса ≈3 млн). Задача — не «построить с нуля», а **управлять ростом**: снимать узкие места (пробки, дефицит товаров, нехватка жилья/работы), строить транспорт и логистику, балансировать бюджет. Город растёт сам, игрок задаёт направление и скорость.

## 2. Три вложенных цикла

| Цикл | Длительность (реально) | Игровое время | Что делает игрок | Обратная связь |
|---|---|---|---|---|
| Минутный (тактический) | 10 с – 3 мин | часы – день | замечает проблему (пробка, переполненный автобус, дефицит), рисует дорогу/полосу, двигает остановку, меняет интервал, ставит зону | машины едут/стоят, цвет оверлея V/C, всплывающие «+/−» у зданий, звук стройки |
| Сессионный (стратегический) | 20 – 90 мин | 1 – 12 месяцев | проектирует линии метро/трамвая, промзону с товарной цепочкой, ж/д между городами, меняет налоги, берёт кредит | месячный отчёт бюджета, графики населения/спроса, достижения, рост репутации |
| Долгий (мета) | несколько сессий | годы | выводит город в следующий «масштаб», связывает регион в агломерацию, выполняет сценарии | новые разблокировки, сценарные цели, статистика «до/после» |

### 2.1 Минутный цикл (ядро «увидел → исправил → увидел результат»)
1. **Наблюдение**: оверлей или оповещение (см. 06) указывает на проблему.
2. **Диагностика**: клик по объекту → инспектор (дорога: V/C, скорость, поток; здание: жители/рабочие места, счастье, причина недовольства; линия ОТ: пассажиропоток, загрузка, окупаемость).
3. **Действие**: инструмент (ниже). Стоимость списывается сразу, эффект — через ближайший пересчёт назначения (`assignmentEveryTicks` = 360 тиков = 6 игровых часов) или сразу для видимых машин.
4. **Результат**: изменение индикатора в инспекторе с дельтой «было/стало» через ≤ 1 игровой день.

Правило дизайна: **любое действие должно давать видимую реакцию ≤ 30 с реального времени** при x3 (≈ 6 игровых часов).

### 2.2 Сессионный цикл
1. Обзор месячного отчёта (доходы/расходы, спрос R/C/I, топ-проблемы).
2. Выбор 1–3 целей (мягкие цели, см. 02).
3. Крупный проект (линия метро 5 км ≈ 1,3 млн ₽ путей + станции; промзона + склад + ж/д ветка).
4. Финансирование: налоги, кредит, тарифы.
5. Проверка эффекта через 1–3 месяца по графикам.

### 2.3 Долгий цикл
Рост населения → новые потребности (у больших городов — пробки и дефицит, а не потолок) → новые инструменты (метро, порт, межгородские соглашения) → новые масштабы задач.

## 4. Обратная связь
- **Мир**: машины (LOD-агенты, см. 05), заполненность автобусов, дым промзон, стройки/снос, ночная подсветка.
- **Числа**: верхняя панель (деньги, ±₽/мес, население, Δ за месяц, спрос R/C/I, дата/скорость).
- **Оверлеи**: V/C, стоимость земли, загрязнение, покрытие ОТ, доступность работ, счастье, дефицит товаров.
- **Оповещения**: с порогами из `BALANCE.alerts`, кнопка «показать на карте».
- **Причинность**: у каждого показателя есть «почему» — разложение по факторам (например спрос на жильё = вклад работы +0,12, пробок −0,05, налогов −0,02).

## 5. Порядок тиков симуляции (Web Worker)
```
каждый тик (1 игр. мин):    движение видимых агентов, ОТ-составы, счётчики потоков
каждые 60 тиков (1 час):     экономика: производство, потребление, цены, склады, грузовые заказы
каждые 360 тиков (6 часов):  транспортное назначение (матрица OD → логит → MSA/BPR)
каждые 1440 тиков (день):    рост: спрос R/C/I, апгрейд/даунгрейд зданий, счастье
каждый месяц (30 дней):      бюджет, налоги, кредиты, репутация, отчёт
```
Главный поток получает от воркера только дельты (изменённые здания, агрегаты метрик) через `postMessage` с `Transferable` массивами.

## 5a. Вовлечённость
Онбординг первых 10 минут, «сок» обратной связи, события и приоритетный список фич — 10 (§8 — ТЗ).

## 6. Провал и восстановление
Жёсткого «game over» нет. Отрицательный баланс → рост ставки кредита (`overdraftRatePenalty`), через `bankruptcyWarnMonths`=3 мес — внешний управляющий: налоги принудительно до `taxNeutral+0.05`, стройка заблокирована, пока баланс не станет положительным. Это мягкая неудача.
